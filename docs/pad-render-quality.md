# Pad 桌面图标的绘制质量

## 已确认的原因

7B 桌面显示尺寸为 1024×600，八个图标绘制槽位是 146×146。原资源为 128×128，运行时使用最近邻放大，圆角和内部白色曲线的像素会被重复采样，形成台阶。原资源已有 4×4 超采样，运行时放大仍会损失这些边缘过渡。

旧 RGB565／alpha blit 还包含固定圆角掩码和白色边缘过滤。按当前 SVG 的透明边距检查，在 128 与 146 尺寸下该附加圆角掩码实际影响 0 个有覆盖率的像素，因此它不是这组图标锯齿的主要原因；本次同时清理该历史规则，让图像自身的 alpha 控制轮廓，并避免其他白色素材被误删。

## 实现

- 保留原 SVG 图案与 128×128 矢量坐标，直接生成 146×146 RGB565／alpha8 图标。
- 圆角与内部几何线条的离线采样提高到 8×8，每个最终像素覆盖 64 个采样点。
- 1024×600 桌面的主图标按原尺寸 blit；`DESKTOP_ICON_SIDE` 同时作为资源尺寸与桌面布局上限。
- 其他尺寸采用像素中心对齐的双线性过滤。颜色与 alpha 先按预乘形式加权，再一次合成到 RGB565，透明区域的 RGB 不会污染边缘。
- 同尺寸缩放直接进入原尺寸路径，保留 alpha 合成的逐像素一致性。裁剪保持原采样坐标，支持负起点与局部重绘。

设备图标资源合计 511,584 字节，较旧版增加 118,368 字节，作为静态只读资源内嵌。8×8 超采样在生成工具中完成；运行时缩放使用固定大小的邻点／权重数组，不增加全屏临时缓冲或每图标动态纹理。显示仍由原 C display owner 提交。

## 预览与验证

```sh
python3 scripts/generate-desktop-assets.py --check
cargo run -p app-launcher --features screenshots --example pad-icons-preview -- \
  artifacts/pad-icons.png
cargo test --workspace
./scripts/build-firmware.sh
```

`pad-icons-preview` 使用固定演示时间、模拟 USB／TF 状态与两个后台应用；只经过真实 Rust 桌面渲染路径，不采集设备画面或用户数据。质量对比的局部图以最近邻放大，保留实际输出像素与边缘覆盖率，避免后期平滑掩盖原始台阶。

新增图像采样检查覆盖白色角部、透明度合成、透明 RGB 污染、渐变边缘、原尺寸一致性、负起点与裁剪坐标，以及非法尺寸／短缓冲。原工作区测试继续检查桌面八图标触摸路由、应用生命周期与时钟局部重绘。

资源复现通过，Rust workspace 93 项测试全部通过；ESP-IDF 6.0.2 构建与三项固件分区的设备写入校验通过。用户在实板确认“明显更细腻，效果合适”，桌面图标边缘观感验收通过。

资源复现、构建、设备写入与用户的实板反馈分别记录在 [acceptance-pad-icon-quality.json](acceptance-pad-icon-quality.json)。合成预览用于像素对比，未作为设备绘制性能测量。
