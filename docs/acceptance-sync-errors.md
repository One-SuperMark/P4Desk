# 同步错误弹窗与烧录后画面偏移处理

日期：2026-10-07。分支：`codex/folio-ui`。记录源码、构建、刷写和实屏确认的独立证据。

## 同步失败根因

在旧设备固件上，通过已安装 Mac 应用的 `--sync-current` 使用现有配置复现：设备连接成功，153,825 字节字体传输后，`sync_commit` 返回固定错误码 `font_read`。

`GenerationStore::commit()` 原先在 `sync_all()` 后仍持有字体写句柄，又重新打开该文件进行 SHA256 和字形覆盖验证。FatFs 文件锁禁止在写句柄存续期间再次读取，因此拒绝提交。修复将关闭写句柄移到读取校验之前；仍然检查长度、SHA256、字库结构和字形覆盖，全部成功后才发布完整资源代。失败保留上一有效代，abort 后允许再次同步。

## 错误展示

- Mac 同步和文件操作的重要失败通过带“关闭”按钮的 Alert 显示。底栏用于连接和进度状态，协议操作名不作为错误说明；成功结果也已按后续的[消息弹窗规则](notifications.md)统一显示。
- Pad 同步失败、资源恢复失败、自动保存失败和重要操作失败使用屏幕中央弹窗，支持 X、“关闭”和 Back；遮罩阻止底层误触，关闭后保留当前应用。
- 错误类型由调用方明确指定，普通状态文字不自动触发弹窗。相同可见错误去重，旧关闭事件不能关闭后来出现的新错误。
- Mac 实际界面已复现 `font_read` 的中文错误弹窗，点击关闭成功，原文件页面和正常底栏恢复。

## 烧录后画面右移

用户确认整幅画面右移，复位按钮或重新上电可恢复。只读检查未发现累计 `x_gap`、错误帧缓冲基址或布局位移：面板 GPIO33 硬复位实际执行，display owner 以 x=0 提交，PPA 坐标与 stride 固定。

本轮修正烧录工具的启动时序：写入成功后 `--after no-reset` 留在 ROM，释放 esptool 串口，再通过 ESP-IDF Python 打开预置 DTR/RTS 的 CH343 串口，稳定 200 ms、RTS 复位 100 ms、释放后保持 500 ms 再关闭。写入失败不执行启动复位。日志监控也预置控制线，省略 `--reset` 不主动复位。

该调整隔离 EN 释放与串口关闭的紧邻时序，**尚不能据此认定硬件根因**。操作系统／USB 驱动可能产生控制线瞬态；画面位置必须由本次刷写后、尚未手动复位的实屏反馈确认。
