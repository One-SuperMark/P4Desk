## USB 副屏性能优化

用户最初反馈电脑窗口约 10 FPS，数据线为 Type-A 到 USB-C。早期系统实际协商 Full Speed；后续刷写／复位后，同一连接路径实际协商为 High Speed 480 Mbps（`Device Speed=2`、`USBSpeed=3`，两者属于不同枚举体系）。未确定协商速度改变的原因，不能归因于编译优化。

固件改为 `-O2`，先用 PPA 完成 180°／可见区域复制，随后与 LCD 扫描重叠执行解码。最终由 Mac 在 GPU 上只旋转可见的 1024×600，P4 将 JPEG 直接解码到空闲 LCD 缓冲。三缓冲状态和唯一 display owner 保留；SDK 6.0.2 的项目内 DPI 扩展观察实际 DMA 源读取完成，当前扫描缓冲不能被写入。LCD 仍扫描 600 行，分配 608 行仅容纳 JPEG MCU 尾部，直接路径没有全屏像素复制。

主机同时保留“正在编码一帧＋最新待处理一帧”及“正在发送一帧＋最新待发送一帧”，目标 60 FPS；ScreenCaptureKit 使用原生回调频率，再在编码入口按目标限流。性能导出在显示保存窗口前冻结统计；后台捕获期间持有允许系统正常休眠的活动租约。编码器硬件状态查询不受支持，因此记录为未知，未宣称 Mac 使用硬件 JPEG。

## USB 副屏清晰度与颜色调整

用户明确表示当前速度满足使用，后续优先解决“文字和图片都模糊、橘色会发红”。只使用自制 1024×600 测试图进行编码数值分析，没有将用户屏幕像素写入日志或交付记录。

定位到两个主机问题：原 VideoToolbox JPEG 在请求质量 0.78、0.95、1 时实际均为 4:2:0，保留较少色度细节；自制原色／橙色色块的实际 YCbCr 与完整范围 BT.709 一致，但码流没有矩阵标记，板上使用 BT.601。ImageIO 最高质量输出则是有 JFIF 标记的 4:4:4，符合完整范围 BT.601。板端固定 SDK 的 DMA2D BT.601 矩阵使用视频有限范围，因此另加入项目内 `jpeg_full_range` 生成源扩展。全局 SDK 的 JPEG／DMA 调度源 SHA 未改变。

现在主机显式使用 sRGB、ImageIO 质量 1，读取实际 SOF 采样并验证 P4 支持的分量顺序、8 bit SOF0、完整 SOI／EOI、1024×600 和 JFIF。超过 1 MiB 才按有限质量梯度重新编码，复用同一份已旋转像素；最终仍超限则不发送。JPEGEncoder／LCD 缓冲继续有界，画面与触摸方向代码保持已确认组合，Pad 画布不经过新的 JPEG 颜色矩阵。

生产编码代码自制图检查覆盖 0°／180°、高熵图超限回退、再次 start／stop 共五个场景。普通细字图使用质量 1／4:4:4／一次编码，180° 帧为 322,083 字节；高熵图降到质量 0.99／4:2:0／两次编码，816,756 字节。每帧实际参数与诊断一致。软件解码的细字边缘平均绝对误差为 0.3916（旧 VT 0.78 为 12.13），橙色色块平均偏差 R −1、G 0、B 0，灰阶误差 0；这些数值证明主机编码改善，不作为实际 LCD 颜色的量化证明。

新增 Swift JPEG 回归八项，全套 **49 项通过**；JPEG 生成器／真实 SDK 位域／矩阵／作用域／下一 DMA 事务／SDK 隔离 **八项通过**。ESP-IDF 6.0.2 完整编译链接通过；生成 JPEG 源仅编译一次，JPEG、runtime、DPI 均核实 `-O2`。本次固件 **2,186,656 字节**，SHA256 `77e46dca8e534c342fc57189e4308645932e1f6fd4d33521f9620048058dd5ee`，三个设备写入 Hash 验证通过；保留 NVS／存储／设置分区，没有调用 TF 格式化。没有独立 UART 启动日志，不据此宣称新的启动稳定性记录。

Mac arm64 Release 及 Developer ID 安全时间戳／Hardened Runtime／deep strict 校验通过，已安装到 `/Applications/P4Desk.app`，安装版与构建版主二进制 SHA256 均为 `5d7e21674be665d01dc080ba0aef7f8f29e16cafe05e9516b08f9797e5de2d51`。没有执行 Apple 公证。

新版实机 HS 480 Mbps 自制移动文字场景观察 30 秒：**1407 帧有效回执／发送，46.9 FPS，捕获回调至回执 P95 100.66 ms**；JPEG 均值 208,474 字节，4:4:4／质量 1／一次编码／无大小回退，设备复制 P95 为 0、解码 P95 13.44 ms、完整 OUT P95 23.7 ms，JPEG 字节数不一致为 0。45 秒测试窗口正常结束。该短测确认 4:4:4 的真实硬件解码、600 行几何和直接缓冲兼容，未将设备回执视为光学显示或实际色彩证明，也不承诺任意办公画面的固定 FPS。

刷写后显示中文细字、RGB／橘色色块、渐变和包含 16／235 的灰阶测试窗口。用户在实板回复 **“文字更清晰，橘色正常”**，本次所询问的文字清晰度改善和橘色偏红修正验收通过；随后关闭测试窗口恢复普通副屏。没有将该回复扩大为所有图片逐像素色彩、全部触摸手势或长期稳定性的验收。面板原生仍为 1024×600 RGB565，ImageIO 质量 1 仍是有损 JPEG。完整数字证据见 [acceptance-usb-quality.json](acceptance-usb-quality.json)。
