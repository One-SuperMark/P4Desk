# 文件管理开发与验收记录

日期：2026-10-07。分支：`codex/folio-ui`。基线提交：`e3b5e46e189365e6792ae07c1797370e3626a6ee`。以下为开发验收时的历史记录，记录时尚未提交或推送。

## 实现

- 保留 Rust tiny-flutter／tiny_gfx 和 ESP-IDF C HAL；文件操作使用一个后台工作线程，耗时 I/O 不进入 UI 状态锁。
- 目录直接上下滚动，只布局可见行；文本预览分块布局并上下滚动。没有左右分页按钮或常驻右侧检查器。
- 单击文件显示物理屏幕中央的详情窗；文件夹主体进入目录，右侧更多入口提供文件夹管理操作。拖动取消按钮点按。
- 支持搜索、排序、新建文件夹、重命名、复制／移动、回收站／恢复／永久删除，UTF-8 文本和 PNG／JPEG／BMP 预览。
- Mac「文件」页通过原 USB vendor 协议浏览、创建文件夹、上传普通文件；文件接收、关闭、持久化、TF 重读 SHA256 和发布分开执行。
- 独立文件字库不替换系统或便签字库；有界索引与缓存、双槽指针保留上一有效版本。

具体使用和格式／资源边界见 [文件管理](file-manager.md)，wire 格式见 [协议 v1](protocol-v1.md)。

## 发现并修复的实机问题

首次上传失败，但 TF 根目录和 Downloads 列表成功。实机固定错误码为 `not_found`／errno 2。

ESP-IDF 6.0.2 使用 picolibc，Rust 标准库的 libc 若没有全局 `espidf_picolibc` cfg，会用旧 newlib 的 `O_CREAT` 值。新建临时文件被 C VFS 当成打开已有文件，因而失败。CMake 已将 cfg 同时传入项目与 build-std，并在目标 FFI 层检查 C／Rust 的 open 标志、stat／dirent 布局，阻止类似 ABI 漂移。修复后真实文件上传通过。

连续字体更新还暴露 FatFs 的 rename 不覆盖已有目标；字体指针改为两槽持久化，先验证与关闭，再替换较旧槽，启动尝试最新有效字体并回退。

### 尚需实机覆盖

当前窗口不覆盖所有容量／文件组合或长时间运行；真正的断电写入中断、TF 空间耗尽、物理拔线和持续大图预览要单独验收。主机测试中的中断／损坏用例不替代这些实机场景。
