# 可关闭消息弹窗

一次性操作提示统一使用可关闭弹窗，禁止添加全局常驻提示条。该约定已加入根目录 `AGENTS.md`。

## Pad

- 成功／信息调用 `LauncherState::show_notice(SystemNotice)`，错误调用 `show_error(SystemError)`。
- 弹窗的内容与 ID 由统一模型管理，UI 通过 `active_dialog()` 读取，X、“关闭”、Back／Kill 关闭当前弹窗。
- `dismiss_dialog(id)` 只关闭匹配 ID；已经失效的关闭事件不影响新弹窗。
- 待显示消息最多 8 条，同类消息去重。错误优先，成功消息不能覆盖尚未关闭的错误。
- “便签与字体已同步”、Wi-Fi 不支持的认证方式、监控配置保存／清除等一次性信息以弹窗显示。文件操作错误也使用统一弹窗。
- `notice` 字段只保留 USB 副屏连接／首帧等待与创建失败页面状态，UI 不再绘制全局 notice 横幅。
- 输入字段的即时验证、网络连接状态、TF 未就绪页和正在进行的操作属于页面状态。后台采样／自动重连不反复弹窗。

文件请求区分显式操作和自动读取：用户操作使用 `apply_files_response`；自动目录刷新使用 `refresh_request_silent()` 标记对应 revision。旧回执不更新当前请求、不弹窗，自动读取失败只更新存储状态。

## Mac

- 同步、上传、文件夹创建、监控配置和诊断导出等结果经 `setNotice` 统一进入可关闭 Alert。
- 当前通知关闭后再展示等待通知，等待队列最多 8 条；相同通知去重。
- 自动页面读取、USB 重连和后台状态查询保持静默。底栏显示连接／进行中进度，操作结果不滞留在底栏。
- CLI 诊断使用 `suppressNotices`，同时抑制成功、警告和错误弹窗。

本轮构建、刷写及实际弹窗结果记录在 `acceptance-notifications.json`。
